# AGENTS.md

The cookout: a self-hosted, Slack-style board for people and agents. Spec: mattpocock/cookout#1.

- [GLOSSARY.md](GLOSSARY.md): the domain language. Names in code use its terms.
- `pnpm check` runs every check, as CI does. Run it once before you finish; it must exit 0. It waits while another `pnpm check` runs on the machine ([ADR 0036](docs/adr/0036-one-pnpm-check-at-a-time-per-machine.md)).
- `pnpm coverage:changed` runs the tests and lists, as `file:line`, every uncovered line or branch in files changed against v1. Run it before `pnpm check` to catch a coverage gap early.
- `pnpm merge-ticket <N>` merges ticket-N into v1. If it stops on a conflict, resolve it and commit on merge-ticket-N, then run `pnpm merge-ticket <N> --continue`: it checks and pushes. Its local check is only the fast ones (types, lint and hygiene, which holds the migration and ADR guards); CI is the merge's full check. It pushes the merge to merge-ticket-N (or, if origin already has merge-ticket-N at that commit, doesn't push it again), waits for that branch's Check run, and only when every job is green fast-forwards v1 to that exact commit (never forced), then deletes merge-ticket-N. If v1 moved, either run merges the new v1 into your merge, keeping your fixes, and stops only if that merge conflicts; if merge-ticket-N's run is red, it stops and prints the failed jobs, with nothing pushed to v1. Before its check, it runs `pnpm install --frozen-lockfile` if the merged `pnpm-lock.yaml` differs from ticket-N's. It refuses to merge while v1's latest Check run or ticket-N's has a job that is not green, waiting for a run still in progress; only the ticket that fixes a red v1 passes `--fixes-red-v1`. It refuses a merge whose migrations list doesn't begin with origin/v1's, entry for entry; only a ticket that moves a migration production hasn't run passes `--reorders-undeployed-migrations`, which compares with the newest `deploy/*` tag instead. After it pushes, it waits for the Check run of the merge on v1 and fails if any job is red.
- `pnpm ci:wait` waits for the Check push run of HEAD, polling every 30 s, prints each job's conclusion and each failed job's failed steps and last 20 log lines, and exits 0 only if every job passed (a job that failed only on a time budget warns). It judges the commit, not one run: the commit is green if any completed run on it succeeded, a cancelled run never counts as red, and if every run on it was cancelled it reruns the newest once (`docs/adr/0069-a-commit-is-green-if-any-completed-run-on-it-succeeded.md`); merge-ticket's waits do the same. `pnpm ci:wait --sha <sha> --branch v1` watches a merge on v1. Use it to wait for CI; never hand-write `gh run watch`, and never pipe a watch, since a pipe hides its exit code.
- Don't run fix, format or lint commands yourself. Commit, and the pre-commit hook fixes and formats what you staged; then fix by hand only what it prints as left over: each new violation once, as `file:line rule message`, then "N new violations in M files". Commit with `scripts/commit.sh`, which takes `git commit`'s arguments: lefthook skips the whole hook when nothing is staged, so it fails then with "nothing staged: run git add first".

- Only Matt approves a domain term. A term counts as approved only with a dated decision of Matt's cited next to it, in an ADR under `docs/adr/` or a comment on a mattpocock/cookout issue; without one it stays proposed.
- In a git worktree, create files with the Write tool (not `cat > … <<EOF`), run every command from the worktree root, and add root dependencies with `pnpm add -w`.
