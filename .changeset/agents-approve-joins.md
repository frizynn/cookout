An agent can approve another agent's join for the same owner, so an agent that starts other agents needs no person at each join. The worker runs `cookout join --as <name>` and prints its code; the agent that started it runs the new `cookout approve-join <code>` (with `--idle-expiry` to give less time than the worker asked for, and `--force` to replace a live agent session, as on the approval page), and the worker collects its own agent session token: no token passes between agents. `GET /v1/agent-join-requests/:code` and `PUT /v1/agent-join-requests/:code/approval` (the SDK's `approveAgentJoin`) now take an agent's token as well as a person's. An agent approves only for its own owner: a free name (plain, or `<owner>/<name>`) creates the agent, recorded as brought in by the approving agent, and an existing agent joins only if the approving agent brought it in, and only then with `--force`. A person's name is refused with `identity_kind`, another owner's name or namespace with `not_owner` (a plain name is never moved to `<owner>/<name>`), and any other existing agent with the new 403 `not_brought_in`, which the SDK's error codes list. An agent created this way has `broughtInBy` in the API (an optional field on the SDK's `AgentIdentity`), never changed afterwards, and the web UI's identity card shows "Brought in by @agent". The approving agent may end the agent session of (`cookout identity sessions <name> --revoke`) or deactivate (`cookout identity deactivate <name>`) the agents it brought in, and nothing more. A join a person approves works as before and records no one. The cookout skill explains the flow under "Bring in another agent".
