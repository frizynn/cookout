# More lint opt-outs, for contradictions

2026-11-22 (mattpocock/cookout#33, extending [ADR 0012](0012-lint-opt-outs.md)). Taking new and moved files to 0 baseline entries found nine more places where the harshest rulesets contradict each other or the cookout's layout, so no code could pass both. Each is off or loosened as narrowly as the contradiction, under ADR 0012's rule that a rule which is only harsh stays on.

- `oxc/no-async-await`, off everywhere. A function that returns a Promise fails `typescript/promise-function-async` unless it is `async`, and fails `oxc/no-async-await` if it is; a `.then` chain instead fails `promise/prefer-await-to-then`. The SDK is plain TypeScript and returns Promises, so it can't avoid them. Backend code still can't be `async`: `effecttsgo/async-function` bans it there.
- `oxc/no-rest-spread-properties`, off everywhere. Copying an object with one field changed is either `{ ...object, field }`, which it bans, or `Object.assign({}, object, { field })`, which `prefer-object-spread` bans; `Object.assign(Object.create(null), …)` gives `any`, which the `no-unsafe-*` rules ban. Like `oxc/no-async-await`, it guards against engines older than the cookout's ES2024 target.
- `vitest/prefer-to-be-truthy` and `vitest/prefer-to-be-falsy`, off everywhere. They ask for `toBeTruthy()` over `toBe(true)`, and `vitest/prefer-strict-boolean-matchers` asks for the opposite. The strict matcher stays, since it fails on a value that is only truthy.
- `typescript/promise-function-async`, with `checkArrowFunctions: false` in backend code (`app/main.ts`, `server.ts`, `lib/server/`, `tests/server/`). There the only Promise-returning functions are the arrows handed to `Effect.promise` and `Effect.tryPromise` to call plain-TS code such as the SDK, and `effecttsgo/async-function` bans the `async` the rule asks for.
- `one-var`, `"never"` instead of the default `"always"`. With `"always"` every scope has one `const` statement, and `sort-vars` sorts its declarators by name, so a declarator that uses another declared later in the alphabet is a use before definition. It also leaves no place to bind a value after a statement in `Effect.gen`.
- `typescript/prefer-readonly-parameter-types`, with `treatMethodsAsReadonly`, and Effect's `Effect`, `Layer`, `Schema.Constraint`, `Exit`, `HttpClientRequest` and `HttpClientResponse` allowed. Effect's values are immutable, but their interfaces declare `pipe` as a method and carry internals the rule reads as mutable, so without it no function could take an Effect, a Schema, an Exit or an HTTP request or response as a parameter.
- `unicorn/no-array-method-this-argument`, off in backend code. It reads every two-argument call to a function named `map` or `forEach` as an array method given a `thisArg`, so it fails Effect's documented `Effect.forEach(items, f, { concurrency })`, `Effect.map(effect, f)` and `Array.map(items, f)`, which `effecttsgo/prefer-effect-array` asks for.
- `node/no-sync` and `node/no-top-level-await`, off in `scripts/` and `lint/`. A script entry must use the sync file APIs, a top-level `await` or a floating Promise (`typescript/no-floating-promises`), and `unicorn/prefer-top-level-await` asks for exactly the top-level `await` that `node/no-top-level-await` bans. Scripts that wait on child processes (`check.ts`, `pack-smoke.ts`) await one `main()` at the top level. The local rules in `lint/rules/` run inside Oxlint's JS plugin host, which calls synchronous visitors.

ADR 0012's `vitest/no-standalone-expect` loosening also counts `it.effect.each` as a test block, which is how the storage contract tests run each test on both Layers without a loop around them (`vitest/prefer-each`).

One disable directive is allowlisted in `lint/allowed-directives.json`: `typescript/no-deprecated` on ajv's `unicode: false` in `scripts/lib/validators.ts`. ajv 8 marks the option deprecated but still honours it, and it is what compiles `minLength` and `maxLength` to `.length` rather than a `require()` of ajv's runtime that crashes the ESM build.
