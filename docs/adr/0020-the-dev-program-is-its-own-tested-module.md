# The dev program is its own tested module

2026-11-22 (the code review of mattpocock/cookout#31, part of mattpocock/cookout#17). Supersedes the parts of [ADR 0017](0017-a-dev-program-entry-runs-the-local-cookout.md) that put the dev program's commands in `testing`, and of [ADR 0015](0015-tests-sit-at-the-fewest-tested-interfaces.md) that list the tested interfaces. A chief-of-staff choice, pending Matt's review.

ADR 0017 kept `start` and `seed` in `testing`, so that no new module was needed, and their tests sat under `sdk/tests/server/`, so they passed the `TESTED_INTERFACES` allowlist though they test the dev program, not the SDK. The commands now live in their own module, `dev` (`devCommandLine` in `dev/server.ts`), which only `app/dev.ts`, `testing` and tests may import (`dev-only-from-the-dev-entry`), and which no published entry may reach. `dev` is on `TESTED_INTERFACES` and its tests are in `dev/tests/server/`, driving the commands as `pnpm dev` and `pnpm seed` do, in process through `testing`'s `runDev` and `startDev`. The one test about the process itself (Ctrl-C exits 0 and deletes the database) spawns `app/dev.ts`, so that file joins `cli.test.ts` as the only places a test may spawn a program. `testing` no longer holds the dev program, so `app/dev.ts` no longer imports it. [ADR 0018](0018-api-stability-leak-off-where-the-platform-is-a-requirement.md)'s opt-out from `effecttsgo/api-stability-leak` moves with the code: it covers `dev` as it covered the same code in `testing`. Off the list if the dev program's commands ever become `cookout` verbs, which ADR 0017 rejected because the published binary must not reach the webhook fake.
