# 0010: Tests run effects with @effect/vitest

2026-11-22. Effects run only in program entries, and tests of Effect code still have to run them. The spec (mattpocock/cookout#17, decision 5) had `app/modules/testing/` own the one test runtime and hand tests Promise-returning functions. Matt chose `@effect/vitest` instead ("Or @effect/vitest"; `@effect/test` was 0.1.0 and "WIP.", while `@effect/vitest` 4.1.5 matches `effect` 4.1.5). Tests run effects with `it.effect` and `it.layer`, which provide `TestClock`. `testing` stays the test composition root: it builds the test Layers (a cookout on port 0, memory or fresh-file SQLite storage, test secrets, an unusable store) and never runs them. Effects run only in `app/main.ts` and in @effect/vitest runners; `Effect.run*` and plain `vitest` stay banned in tests. Tests then read like the Effect code they test, and time moves only through the test clock. Supersedes #17's decision 5. Sources: wiki `chief-of-staff/cookout/decision-perfect-ts-rewrite.md` (2026-11-22, "tests use @effect/vitest"); the 2026-11-22 comment on mattpocock/cookout#17.
