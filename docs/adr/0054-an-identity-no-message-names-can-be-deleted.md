# An identity no message names can be deleted

Status: accepted. Supersedes the "no route deletes an identity" part of [ADR 0045](0045-identities-are-deactivated-never-deleted.md).

2026-11-23 (mattpocock/cookout#172). Matt asked on the board (2026-11-23) that e2e checks delete the identities they create, because the People list on the live board had filled with deactivated `e2e-` identities. ADR 0045 deactivates instead of deleting so that a message never loses its author, or seems to come from someone new who takes the name. That reason holds only while a message names the identity, so an admin may now delete an identity that no message names: `DELETE /v1/identities/:name` (`deleteIdentity`, `cookout identity delete`). It removes the identity, its tokens, agent session tokens, read positions, subscriptions, follows, mentions and the command it handles, in one transaction, and frees the name. An identity that a message on the board names as its author, or as its author's owner (an agent moved to another owner keeps its old owner on its messages), is refused with 409 `has_messages`, saying to deactivate it instead; a human who owns agents is 409 `owns_agents`; the last active admin is 409 `last_admin`. Everything else in ADR 0045 stands: an identity with messages is only ever deactivated. Counting the author's owner, `GET /v1/identities/:name/message-count` (which the web UI reads to show Delete or Deactivate), and the deploy job's sweep of the `e2e-` backlog are chief-of-staff choices, pending Matt's review. A delete is not sent on the live stream; other open web UIs drop the identity on their next load.
